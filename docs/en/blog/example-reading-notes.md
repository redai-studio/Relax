Start with **one concrete question**, then follow the entry point, call sites, and return values. A useful reading note can follow the same structure as a [debugging note](./example-debugging-notes.md).

This article tests the blog layout. Scenarios and data are illustrative and do not represent actual project results.
:::

## Enter the code with a question

Write down one concrete question before reading. Looking for an entry point, call sites, and return values makes it easier to form a reading path than trying to remember every module at once.

## Leave the reading path for others

### Entry point

Record where you started reading and why.

### Data changes

Choose a simple input and describe the changes it goes through along that path.

### Open questions

List branches you have not read and behaviors you have not confirmed.

## Keep the note lightweight

There is no need to copy the source into the article. A short explanation, accurate links, and one example are often enough for readers to continue.
