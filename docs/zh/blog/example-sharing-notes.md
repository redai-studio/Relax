::: info 示例文章
本文是博客展示用的样稿，用于检查长标题、目录和文内链接，不是一篇正式发布的团队文章。
:::

团队笔记的读者往往知道前因后果。把笔记分享给社区时，我们需要补上那些平时可以省略的背景：为什么遇到这个问题、已经尝试过什么，以及哪些问题还没有答案。

## 给文章一个明确的起点

第一段可以回答三个问题：

- 这篇文章想讨论什么？
- 读者需要知道哪些背景？
- 读完之后，可以继续做什么？

> 一篇文章不必覆盖整个系统，但应当交代自己讨论的范围。

## 让内容可以顺着读下去

### 用小标题组织过程

把准备、观察和结论分开，读者就可以根据需要跳转。右侧目录也会给较长的文章提供一条阅读路径。

### 给代码保留上下文

例如，预览这个仓库的文档站，可以在项目根目录运行已有的命令：

```bash
npm run docs:dev
```

说明命令运行的位置和目的，比单独贴一行命令更容易复用。涉及长路径或代码标识符时，也可以使用行内代码，如 `docs/zh/blog/example-sharing-notes.md`。

## 发布前再读一遍

- [ ] 标题和摘要能否说明文章主题？
- [ ] 示例和实际观察是否区分清楚？
- [ ] 链接是否指向读者能够继续阅读的内容？
- [ ] 中英文版本是否覆盖相同内容？

完成这些检查之后，文章就更容易成为后续交流的起点。
