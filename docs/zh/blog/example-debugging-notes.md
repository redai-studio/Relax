一次排查结束之后，最容易留下的是解决问题的那条命令。可是几周后再看，我们往往已经忘记了为什么运行它、它验证了什么，以及当时排除了哪些可能。

一篇有用的笔记，可以从这些问题开始。

## 先把现象说清楚

假设我们观察到一个任务变慢。先记录可以重复观察到的现象：什么时候开始、哪些步骤变慢、同样的输入能否复现。

> 把“感觉变慢了”改写成一个可以验证的问题，是排查的第一步。

| 记录项 | 示例内容 |
| --- | --- |
| 触发条件 | 在同一组输入上重复运行 |
| 观察对象 | 某一步骤的耗时 |
| 对照条件 | 保持输入和运行环境一致 |

## 一次验证一个假设

### 保留原始观察

汇总数据之前，先保存每次观察的值。下面的代码只演示如何整理三次测量，不对应真实训练任务。

```python
from statistics import mean

# 示例数据，单位为秒。
durations = [3.4, 3.1, 3.8]
summary = {
    "runs": len(durations),
    "mean_seconds": round(mean(durations), 2),
    "max_seconds": max(durations),
}
```

### 写下没有验证的部分

一次局部实验只能回答它覆盖的问题。若只测试了一个输入规模，就记录这个范围；若修改同时影响了两个条件，就保留不确定性，安排下一次对照。

## 给下一位读者留一条路径

笔记的最后，可以交代复现条件、关键观察和下一步。即使暂时没有最终结论，别人也能从已有证据继续工作。

- 保存能复现现象的最小输入。
- 链接相关代码或已有文档。
- 区分观察结果和仍待验证的推测。
