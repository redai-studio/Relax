### 退化定位：视觉编码器

保持同一评测协议，分别替换语言与视觉模块权重，四组均完成191题：

| 语言权重 | 视觉权重 | 正确数 | Pass@1（%） |
| -------- | -------- | -----: | ----------: |
| Base     | Base     |    131 |       68.59 |
| SFT      | SFT      |     71 |       37.17 |
| SFT      | Base     |    146 |       76.44 |
| Base     | SFT      |     70 |       36.65 |

换上SFT视觉权重即出现明显退化；保留SFT语言、恢复基座视觉可恢复表现。这将问题定位到训练后的视觉分支。混合权重用于因果定位，原全参SFT基线仍为验收失败。

逐题核查可见视觉信息未被正确使用：第0题原图是小吃摊上的蓝色一次性手套，SFT描述成红黑摩托车皮手套并编造品牌；第12题木船上的蓝色拖鞋被描述为圣诞服人物的黑靴；第13题河岸绿色推车被描述成商店银色购物车。恢复基座视觉后，这三题均恢复正确图片描述和答案。

原生HF视觉前向的模块替换对照进一步指向编码器trunk：对同一图片，仅更新merger时输出与基座cosine为0.9964，仅更新trunk时为0.0336；完整SFT视觉为0.1077、norm为基座的2.62倍。256-token图片预算下同样明显漂移，不能只归因于评测使用1024-token图片。

已验证的实现不变量：

- 最终native→HF视觉333项独立逐值完全一致；正式Blackwell硬件上的零更新HF→Megatron→HF共1811项，在目标dtype转换后全部逐值相等，30个GDN norm由FP32导为BF16。
- 实际packed batch在真实Gloo DP8/EP8下重放，所测64条样本映射的tokens、loss mask与pixel/grid对应一致；视觉333参数均走dense梯度同步。
- 正式Blackwell硬件的固定图像、固定上游梯度对照中，base/SFT各测无重算、无重算重复、full重算，六次全部333项梯度有限；开启重算未出现超过重复运行差异量级的梯度放大。该检查使用与训练一致的FA4关闭配置，实际backend为FusedAttention。

这些检查未复现显著转换或重算故障，但尚未覆盖真实训练中的全部输入及上游梯度。下文记录保留1081步学习率调度的200步对照及完整冻结主干实验；原大尖峰的具体触发机制仍未定位。

本机使用私有兼容入口恢复Transformers配置继承、绕过故障卡的全局显存探测，并将视觉Conv3D patch embedding按相同权重展开为等价linear运算；未改权重、提示和评分协议。兼容入口SHA256为 `203651b0421e3c6f6da1f3f8901b3d547d10bbef3aefa075291fbbf9ba8472cf`。

实际评测的 `vstar_benchmark.py` SHA256为 `4135bf39ee5bb78d8ad2b4b79e539c5c91b62b3a517b76efb7ffc3507cefacd1`，`benchmark.py` 为 `108f2caf8756f113f65a35a3e43fb16e779ccd46ddf4373cab5adb2dd13a5300`。逐题原始答案、协议、模型来源与复核记录保存在仓库外。

### 遗留问题：grad norm spike与早期loss回升，待定位

全程25步的grad norm超过10，其中4步超过100；step 462达到2243.31。该指标为裁剪前的全局norm，`clip_grad=1`确实生效，但不能据此认定更新稳定。固定验证集loss从step 100的0.44626升至step 200的0.51435，后半程逐渐回落，step 1000为0.43287。后期loss改善与V\*Bench明显退化同时存在；训练、评测正常跑完不代表梯度尖峰问题已解决，也没有证据证明尖峰直接造成此次退化。

已核查实际EP8按token归一化链路，未发现重复缩放；原全参实验中，语言、视觉与投影层均参与训练并使用同一学习率，MoE aux loss系数为0。全参峰值学习率偏大、router负载变化仍是待验证假设，原尖峰缺少分模块梯度和expert负载/熵证据。下述独立重跑未复现原来的百级尖峰，不能据此认定其触发机制已解决。

### 冻结视觉主干：200步修复对照

[冻结主干启动脚本](../scripts/run-qwen3.5-35B-A3B-freeze-vit-8xgpu.sh)使用现有`--freeze-vision-model`：冻结327个trunk参数，merger的6个参数和语言部分继续训练。该脚本默认运行完整1 epoch。下述短跑保持原数据、seed、GBS32、TP1/PP1/CP1/EP8、full重算和2e-5学习率，并显式使用`--lr-decay-iters 1081`保留原warmup/cosine调度，仅在200次更新后结束。

以下各组均完成同协议的191题评测；200步模型来自独立重跑，不是原失败1 epoch实验的中间checkpoint。

| 模型                                | 更新数 | 正确数 | Pass@1（%） |
| ----------------------------------- | -----: | -----: | ----------: |
| Base                                |      0 |    131 |       68.59 |
| 原全参配置独立重跑                  |    200 |    112 |       58.64 |
| 上述200步语言＋Base视觉，仅用于定位 |    200 |    128 |       67.02 |
| 冻结视觉主干，训练merger与语言      |    200 |    139 |       72.77 |

冻结组比同期全参重跑多答对27题，比Base多答对8题。验证loss在第100/200次更新时，原配置重跑为0.44434/0.46252，冻结组为0.43824/0.44639。

两次训练的200个数据边界完整字典、记录的pack长度与microbatch聚合指标、GBS和各组学习率逐值一致。全参重跑的首步loss与原失败实验相同，但首步grad norm已不同，loss从step 2开始分叉；其最大norm为15.39，仍出现下游退化，不能把旧实验的百级尖峰视为退化的必要条件。

冻结组导出后327个trunk参数与Base逐值相同，固定图片的pre-merger特征也逐值相同。相同Blackwell运行环境、相同1024-token图片输入下，最终视觉输出相对Base的cosine为0.99788，同期全参重跑为0.54067，原失败1 epoch模型为0.10772；256-token预算下结论一致。特征对照用于定位，性能判断以完整191题结果为准。

中期工具策略也有影响：全参200步有38题耗尽工具轮数，换回Base视觉后为29题，冻结训练后为20题。恢复视觉只能解释部分中期退化，不能把所有工具循环或答错都归于ViT。

200步对照与下述完整1 epoch实验共同支持冻结主干的修复方案。原全参1 epoch基线仍为验收失败，原grad norm大尖峰的具体触发机制仍列为遗留问题。
